## T01：暂停不能抹掉在途发送

原实现中，`action('pause')` 和关闭持续监测调用 `resetWake()`，替换 `task.wake`。发送 Promise 仍引用旧对象；这会把已持久化的 `sending` 改成 `idle`。之后的成功或不确定结果落在旧对象上，重启也看不到真实发送阶段。结束监测则可以直接删除仍在发送的记录。

修复位于 `server/manager.js` 的额度监测操作：

- 发送中允许暂停，但保留原 outbox 对象、消息阶段和结果归属。
- 发送结果尚未确认时，拒绝重新开启以及结束并移除记录。
- 结果返回后正常记录计数、队列确认或不确定阶段；暂停状态不会被成功返回重新开启。
- 已经不确定的发送再次暂停时也保留不确定记录；重启后不会自动重发。

回归使用真实 `Store` 和独立目录，检查发送中暂停后磁盘仍为 `sending`，成功后为 `sent` 且累计次数为 1；失败后为 `uncertain`，重启及额度变化不产生发送。

## T02：授权决定必须匹配当前请求与轮次

原实现虽然对详情读取使用 `detailToken`，但 `POST /api/approval` 不核验它，且 `approve()` 没有验证当前轮次或暂停状态。因此旧页面决定、复用的请求 ID 或暂停中的授权仍可能被接受。处理一项授权还会无条件将任务改回 `running`，即使仍有其他请求。

修复涉及 `server/manager.js`、`server/index.js`、`public/app.js` 和 `public/widget.js`：

- 保存请求所属聊天与轮次；决定必须带对应 `detailToken`，并匹配仍处于等待授权状态的当前轮次。
- 页面按钮携带自己实际展示的令牌；不会用新状态的令牌替换旧按钮代表的请求。
- 暂停会拒绝已有待授权操作；暂停期间收到的新请求也拒绝。
- 在 `turn/start` 确认前缓存的授权，不能在暂停之后重放为等待授权并撤销暂停。
- 处理一项后若仍有其他请求，继续显示等待授权。

缺少令牌、过期令牌和失效轮次均不发送批准。正确令牌仍可按用户决定允许或拒绝。真实 HTTP 回归同时检查详情接口、决定接口和过期请求。

由于决定接口的必填参数发生变化，**HTTP 协议版本由 1 升为 2**；状态 schema 仍为 1。旧页面和插件需要重新加载，不能静默按旧格式提交。

## T03：不可完整审阅的内容不进入授权列表

原实现对命令直接 `String(...).slice(0,12000)`，命令末尾可能被省略；对象则显示为 `[object Object]`，仍有允许按钮。独立详情接口返回的只是这份已经截断的记录。

当前只接受字符串命令，最多 12000 个 UTF-16 单元；理由最多 2000 个单元，工作目录必须为字符串或缺省。超长或类型错误的内容直接拒绝，并请求暂停当前轮次，提示到原 Codex 会话核对。有效请求保留完整内容，实时流可以显示预览，详情接口不再把被截断的命令当作完整命令。

回归分别检查 12001 单元命令及对象命令，均不进入待授权列表、不产生批准，并发出中断请求。

## T04：迟到的中断失败不能影响新轮次

复现顺序：发出暂停请求，原轮次已通过完成事件确认中断；用户继续并启动新轮次；旧中断 RPC 随后失败。原 `catch` 会直接把新轮次设为 `blocked`。

当前 `interruptTask()` 捕获调用时的聊天和轮次，只在同一任务仍以同一轮次处于 `pausing` 时记录失败。失效结果直接退出；通知路径和手动暂停共用该规则。手动暂停也不再在迟到返回后继续改写新任务状态。

回归验证旧失败不改变新轮次；另一项回归确认当前轮次的中断确实失败时仍进入阻塞并显示错误。

## T05：部分额度更新不能单独启动工作

原实现对缺少完整窗口的额度事件可能用局部健康额度替换完整快照，直接任务只检查这份显示快照。已知另一个窗口耗尽时，也可能通过检查。

当前 `hasExecutionQuota()` 同时核验显示额度与新鲜的完整主动读取样本。部分事件会使完整样本失效并等待重新读取；调度选择任务及异步准备结束时都执行相同检查。

回归包括已知次要窗口耗尽时收到局部健康通知，以及准备聊天期间收到局部事件，两者均不能启动轮次；完整健康样本到达后可以正常执行。

## T06：冷启动等待也验证数据目录

原 `ensureService()` 首次连接会检查数据目录，但启动后轮询只看应用、构建和协议。端口被同构建、不同数据目录的服务占用时可能错误连接。

当前抽取同一套 `verifiedService()` 校验用于两个入口；发现错误目录或不兼容服务时明确失败。只有连接被拒绝才继续等待，不吞掉已经取得服务身份后的不匹配。

回归通过隔离子进程模拟“首次未运行，启动后返回相同构建但错误目录”，不启动真实服务，确认明确拒绝。既有真实 MCP 冷启动回归继续通过。

## T07：HTTP 分片不能损坏中文输入

原 `content += chunk` 会分别将每个 Buffer 解码。截在汉字中间时，原始实现把 `核对中文😀验收标准` 读成 `���对中文😀验收标准`，JSON 依然合法，损坏的目标会继续保存。

新增 `server/http-body.js`，使用严格流式 UTF-8 解码。保留 40000 个 UTF-16 单元上限，同时限制 160000 字节；正文必须为对象。非法 UTF-8、未结束的码点及过大正文明确拒绝。

单元回归遍历测试 JSON 的每一个字节切分位置；真实 HTTP 回归将首个汉字拆开分两次写入，核验保存后的中文和表情逐字一致。该服务使用独立目录且关闭调度，没有调用模型。
