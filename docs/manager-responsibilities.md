# Manager 职责拆分

版本：0.5.1。日期：2026-10-29。

`server/manager.js` 保留服务对外入口，负责额度采样、调度准入、任务操作和组件协调。原先集中在 Manager 中的数据迁移、保存与 Codex 轮次协议分别交给以下模块。

| 模块 | 负责内容 | 协作边界 |
| --- | --- | --- |
| `server/state-lifecycle.js` | 默认状态、完成记录清理，以及按模式分发迁移和恢复转换 | 只转换传入的数据，不调用 RPC、保存文件或开启调度 |
| `server/direct-task.js`、`server/monitor-task.js` | 各模式的创建、状态、计数、操作、校验和恢复规则 | 通过 `server/task-model.js` 选择规则；模式说明见 [两种任务的状态模型](task-models.md) |
| `server/state-persistence.js` | 当前状态、保存健康信息、250 毫秒输出合并、立即提交、保存重试与备份替换 | 通过 Store 完成文件操作；保存失败先关闭调度，再通知协调层使旧调度失效 |
| `server/turn-controller.js` | 轮次启动、启动前事件缓存、轮次 ID 校验、输出与完成事件、授权和中断 | 自行管理执行与授权映射；使用明确注入的调度、额度、保存和通知接口，不接收 Manager 对象 |
| `server/manager.js` | 用户操作、额度采样、调度周期和恢复前的运行检查 | 组装组件，保持 HTTP、MCP、健康检查及状态快照使用的现有接口 |

状态由 StatePersistence 持有。恢复备份会替换状态对象，轮次处理每次读取当前对象，避免继续修改已替换的旧任务。恢复时同时取消旧的延迟保存定时器。

保存失败后，未保存标记仍然保留。授权操作先立即提交，再发送决定；额度恢复消息仍由原有发送路径在发送前保存记录。重启后正在执行的工作等待人工确认，发送结果不确定的记录继续阻止自动重复发送。两种任务模式、额度阈值及发送策略沿用原有规则。
