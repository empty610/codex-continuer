# 运行、恢复与发布

当前代码版本来自 `package.json`。`/api/health`、页面版本和 MCP 状态同时给出内容指纹 `buildId`、协议版本和状态 schema 版本；相同语义版本的不同运行代码也能区分。

当前本地 HTTPS 协议版本为 4，状态 schema 仍为 1。所有客户端固定校验数据目录中的服务证书；不兼容旧 HTTP 客户端，升级时需先正常停止旧服务与挂件，再一起切换客户端。授权决定必须携带对应请求的 `detailToken`；升级不迁移或清空真实任务。

## 启动与停止

- MCP 读取状态、列会话或打开挂件时，如果需要冷启动服务，只进入查询模式；不因保存的调度开关为开而执行旧队列。读取现有服务不会改变它原有的运行状态。
- 在页面明确开启调度，或明确创建/继续工作，才退出查询模式。导入原聊天仍保持暂停。服务遇到保存错误后会关闭调度，不能自动恢复执行。
- `npm start` 是明确的后台执行启动入口，会沿用保存的调度设置。`Start-Continuer.ps1` 与挂件入口冷启动时进入查询模式，并打开原生挂件；页面明确开启调度后才启动旧队列。`Stop-Continuer.ps1` 使用本地凭据关闭调度并停止服务；隐藏到托盘保持运行；退出挂件会一并停止服务与监听器，必要时按安装路径核验后结束所属服务进程树。
- `/api/health` 报告服务 PID、构建、额度连接、存储故障、上次退出、挂件就绪状态、自启动监听器和实时连接数。挂件在首屏状态成功渲染后才发送就绪信号，打开命令等待该信号。
- 服务通过规范化数据目录对应的独占命名管道句柄互斥，不增加常驻进程；进程退出后由系统释放。`service.lock` 仅记录 PID 和租约标识，也会拒绝覆盖仍存活的旧版服务。失效记录在取得互斥句柄后更新；损坏记录仍需先检查进程，不能直接绕过。
- 关闭调度、断连或存储故障会使旧调度失效，即使马上重新开启，也由新的有效调度启动任务。异步准备结束后会重新检查连接、开关及额度；已发出的轮次按原有规则继续或明确中断。
- 挂件渲染进程异常退出时最多尝试重新加载 3 次；手动退出挂件不会触发重新打开。服务崩溃不会自动重新开启任务调度，下一次查询冷启动仍为查询模式。主动退出会写入 quit.request，阻止查询和自动启动拉起后台；手动打开挂件才清除。演示模式使用独立 quit-demo.request，不影响真实服务。
- 查询已有服务和等待冷启动完成使用同一套构建、协议及数据目录校验；不能仅凭端口和构建相同就连接其他数据目录。
- 直接执行和原聊天恢复发送均要求新鲜的完整主动额度读取；部分额度通知只更新显示并触发重新读取，不能单独授权启动轮次。
- 隐藏挂件会暂停前端订阅与界面工作，重新显示时取得最新状态；后台调度和额度读取继续按原有设置运行。原生隐藏启动仅保留就绪所需的一次状态握手。

## 数据保存失败与恢复

状态使用 `schemaVersion=1`，启动检查设置、任务、重复聊天、活动与额度历史的基本结构，以及任务模式、布尔开关、次数和发送阶段组合。旧格式可以迁移；缺少耗尽依据的旧待发送记录进入人工确认状态。无法识别、损坏或超过 64 MiB 的文件会进入明确错误状态，不被空任务列表覆盖。

保存先写临时文件并刷盘，再保留上一次有效主文件为 `state.json.bak`，最后替换主文件。演示模式使用独立的 `demo-state.json`。备份和主文件都包含私人工作内容，均保留在数据目录。

保存异常时，服务继续提供查询和诊断，关闭后续调度和续作发送；当前实际运行的工作不会因为保存失败被误称为已暂停。暂停操作仍会尝试中断当前轮次。发送和批准操作前的关键保存失败时，不越过失败去发送或批准。

页面与挂件提供两种明确操作：

1. **重试保存**：保留当前内存状态，修复权限或文件占用后补写；调度保持关闭。发送记录不确定时进入需要检查状态。
2. **恢复上次备份**：先验证备份，保留当前主文件为 `.before-restore`，再恢复。所有恢复记录停止，发送中的记录标记不确定。先检查原聊天和项目状态，再明确继续。备份可能早于最近一次排队发送，不能未经核对直接重放。

如果服务在启动时因目录不可写而无法取得锁，需先修复目录权限；错误写入服务日志。没有有效备份时，不自动清空文件或猜测任务状态，应保留原文件处理。

接口为同源 JSON POST `/api/storage/recover`，正文 `{"source":"retry"}` 或 `{"source":"backup"}`，并需要 `X-Continuer-Client: 1`。有在途续作消息时，两种恢复操作均拒绝，需等待发送结果确认。备份恢复还拒绝覆盖仍在调度、准备或运行的工作。

在途发送可以暂停监测，但保留原发送记录和结果归属；发送结束前不能重新开启或结束并移除该记录。不确定结果也不会因再次暂停而消失，需核对原聊天后再明确继续。

暂停直接工作会拒绝其待授权操作；暂停中的新授权同样拒绝。`POST /api/approval` 正文为 `{"id":88,"decision":"accept","token":"对应 detailToken"}`，拒绝操作时将 `decision` 设为 `decline`。服务核验请求令牌及当前聊天、轮次和等待授权状态；超出可审阅长度或类型错误的授权不会截断后接受，而是拒绝并请求暂停。

## 资源上限

- 输出预览最多 16000 个 UTF-16 单元，结构化摘要最多 2000 个；完整内容在原 Codex 会话查看。
- `/api/state` 和 SSE 只传任务摘要，活动预览最多 240 个字符、日志预览最多 180 个；`GET /api/tasks/{id}` 按需读取完整活动、路径、目标、备注、计划和保留输出。详情只缓存一个选中任务，按任务自身内容变化失效；无关额度刷新不重新读取，迟到响应不会覆盖新选择。
- 组合摘要预算为 768 KiB；需要时进一步精简历史及授权预览并显示说明，磁盘内容不变。长授权通过 `GET /api/approvals/{id}?token={detailToken}` 获取完整内容，在完整命令到达前页面禁用允许操作；过期令牌返回失效。
- 保存最近 300 条活动、240 个额度样本；普通快照带最近 50 条活动。日志导出使用 `/api/logs`，取最多 300 条。
- 最多新建/导入 100 条管理记录；导入提交前也检查上限。会话选择最多保留 300 项，审批最多 50 项，计划最多 100 步。
- 最多 16 个 SSE 连接。每个连接只允许一份未排出的状态，单帧最多 1 MiB；持续背压或 15 秒不排空的客户端断开并由页面重连，不积累历史帧。
- 应用日志单条限制约 16000 字符，达到 1 MiB 时轮转，保留 3 份副本。原生重定向日志在启动时和每 60 秒检查并复制、截短；检查间隔中的突发输出可能短暂超过阈值。
- JSON 请求正文通过流式 UTF-8 解码，跨网络分片的汉字和表情保持完整；无效编码、非对象正文及超过 40000 个 UTF-16 单元或 160000 字节的请求会被拒绝。
- 动画仅在紧凑仪表可见时首次加载，会话列表仅在详细面板可见时按需刷新；隐藏视图不运行仪表和面板定时器。静态资源按白名单懒缓存并支持 ETag/304，编辑资源后会检测变化。

## 位置与便携包

隔离源码目录生成本机包时，可用 `CONTINUER_BUILD_DATA_DIR` 指向原有数据目录；该值仅写入本机构建的 `runtime.json`，便携包仍不包含绝对路径。版本切换应先停止旧服务并备份状态，再打开新版。

本机包保留显式 `runtime.json` 数据路径，当前项目已有的 `data/` 不搬迁。新便携包不包含本机 Node 或数据目录绝对路径，默认使用 `%LOCALAPPDATA%\CodexContinuer`，要求目标电脑安装 Node.js。`CONTINUER_DATA_DIR` 可明确覆盖；`CONTINUER_PORT` 用于插件/挂件端口，服务另兼容 `PORT`。

```powershell
npm run check
npm test
npm run build:plugin
node scripts/verify-artifact.js

# 生成可交付的 Windows 便携市场，不自动发布
npm run build:plugin -- --portable
node scripts/verify-artifact.js dist/portable-marketplace/plugins/codex-continuer
```

构建先在专用暂存目录按白名单复制，再生成并验证完整 SHA-256 文件清单，最后替换正式包；旧包的过期文件不会残留。替换失败时保留原包。验证清单会检查修改、缺失和多余文件。运行中的服务与插件构建不一致时会明确要求重启。

`.github/workflows/windows.yml` 提供 Windows 检查、测试、便携构建和清单验证。官方 Action 固定到发布提交；Electron 在测试前显式安装，避免隐藏窗口测试因缺少运行时而跳过。工作流结果见 [GitHub Actions](https://github.com/empty610/codex-continuer/actions/workflows/windows.yml)，本机验证和托管 CI 分别记录。

回归包含使用独立演示数据和隐藏窗口的 Electron 冒烟测试，检查首屏就绪、隐藏状态和明确退出。受限工具环境若禁止 Electron 读取运行时，应在正常进程权限下运行该测试；不需要关闭应用沙箱或修改运行时 ACL。真实任务状态不用于冒烟测试。

动作参数参考官方 [checkout](https://github.com/actions/checkout)、[setup-node](https://github.com/actions/setup-node) 和 [upload-artifact](https://github.com/actions/upload-artifact)；上传显式包含已校验白名单产物中的隐藏插件清单，避免丢失市场注册文件。

桌面容器使用 Electron，后续优化围绕现有运行架构展开。
